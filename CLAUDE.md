# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Clippo is a **GNOME Shell extension** (UUID `clippo@danielfreitasdev.github.io`) that adds clipboard history — not a standalone app. On GNOME/Wayland only the Shell process can read the clipboard in the background (`Meta.Selection`), register a global shortcut, and place a window at the pointer, so this lives inside the Shell as an extension.

Plain **GJS / ESM, no build step** — the files in this directory *are* the running code (installed via symlink). Targets GNOME Shell 48–50. Code comments are in US English. UI strings are English at the source and localized via gettext (domain `clippo`): translations live in `po/*.po`, compiled to `locale/` by `install.sh`; pt_BR ships, other locales fall back to the English source. A Portuguese README (`README.pt-BR.md`) is also kept for Brazilian readers.

## Development

`install.sh` symlinks the project into `~/.local/share/gnome-shell/extensions/<uuid>` and compiles the GSettings schema. Because of the symlink, edits are "live" on disk — but on **Wayland the Shell cannot reload running JS without a logout/login**, so:

- After editing `extension.js` / `lib/*`: **log out and back in**, then `gnome-extensions enable clippo@danielfreitasdev.github.io`.
- To re-run `enable()`/`disable()` without new code (e.g. testing lifecycle teardown): `gnome-extensions disable clippo@danielfreitasdev.github.io && gnome-extensions enable clippo@danielfreitasdev.github.io`.
- After editing `schemas/*.gschema.xml`: `glib-compile-schemas schemas/` (install.sh also does this).
- After editing UI strings or `po/*.po`: re-run `install.sh` to recompile the `.mo` files (needs `gettext`/`msgfmt`). Regenerate the template with `xgettext --from-code=UTF-8 -L JavaScript --keyword=_ --keyword=ngettext:1,2 -o po/clippo.pot prefs.js lib/*.js` (`lib/qrcodegen.js` is vendored third-party code with no translatable strings).
- Release zip for extensions.gnome.org: `gnome-extensions pack --force --podir=po --extra-source=lib --extra-source=LICENSE .` — keep the shortcut defaults empty and the clipboard-access disclosure in the metadata description (both are EGO review MUSTs).
- Logs: `journalctl -f -o cat /usr/bin/gnome-shell` (emit with `console.*` / `logError` from GJS).
- Interactive inspection: `Alt+F2` → `lg` (Looking Glass).
- Preferences window: `gnome-extensions prefs clippo@danielfreitasdev.github.io`.

No test suite, linter, or package manager — there are no dependencies beyond the GNOME platform. `jsconfig.json` exists only for editor IntelliSense (`checkJs` is off).

## Architecture

`extension.js` is the **orchestrator** and the only stateful coordinator. The `lib/` modules are decoupled — they never reference each other or the GSettings; `extension.js` wires them through GObject signals in `enable()`, pushes settings into them as plain properties (`_applyCaptureSettings()`), and tears everything down in `disable()`.

Data flow on **copy**: `ClipboardManager` (watches `Meta.Selection`) emits `text-copied` (or `image-copied`, when `captureImages` is on and no usable text is offered) → `extension.js` calls `HistoryStore.addText()` / `addImage()` → refreshes `ClipboardPopup` if open.

Data flow on **open** (the open-history shortcut or panel icon): `extension.js` reads `HistoryStore.getEntries()`, then `popup.refresh(entries)` + `popup.show({x,y})`. The popup's signals carry an **entry id** (not the text): `item-selected` / `item-pin-toggled` / `item-removed` / `item-edited` / `action-invoked` / `open-with-invoked` (id + chosen app desktop id) / `clear-requested`. `extension.js` looks the entry up with `getEntry(id)` and translates each into a store mutation plus a refresh (for `open-with-invoked` it resolves a `Gio.DesktopAppInfo` and `launch_uris()` — never a shell command). Selecting writes back to the clipboard via `ClipboardManager.setClipboard()` / `setImage()`.

Components:
- **`lib/clipboardManager.js`** — `GObject` with `text-copied` and `image-copied` signals. Handles `SELECTION_CLIPBOARD` (Ctrl+C) and, when `capturePrimary` is set, the debounced PRIMARY selection. Top-of-`_readClipboard` guards skip capture when paused (`privateMode`), when the focused app is in `excludedApps`, or when the content is flagged sensitive (a `passwordManagerHint` MIME type seen via `get_mimetypes`). Images are read with `transfer_async('image/png')` and written back with `St.Clipboard.set_content`; file-copy images are loaded and re-encoded to PNG **asynchronously** (`read_async` → `Pixbuf.new_from_stream_async` → `save_to_streamv_async`) and `setImage` reads from disk with `load_bytes_async`, so decode/encode and disk I/O never block the compositor. **Anti-loop guard:** our own writes set `_selfTriggered` (500ms safety timeout) plus `_lastText`/`_lastImageHash`, so they aren't re-captured.
- **`lib/historyStore.js`** — plain class (no GObject). One `_entries` array of objects `{id, type:'text'|'image', text|imagePath, hash, createdAt, lastUsedAt, pinned}`, newest-first, with pinned floated to the top in `getEntries()`. Dedup is by `hash` (text = the text itself; image = sha256). Persists to `~/.local/share/clippo/history.json` **atomically** (`Gio.FileCreateFlags.PRIVATE`, so 0600 from creation), **debounced 500ms**; `FILE_VERSION` is **2** and `load()` migrates the v1 `{pinned:[], items:[]}` string format in place. Images are stored as separate PNGs under `images/<id>.png` (0600, written **asynchronously** via `replace_contents_bytes_async`; a failed write drops the entry); `remove`/`clear`/`_trim` delete them and `load()` sweeps orphans. `clear()` keeps pinned entries. The `persist` flag (from `persist-history`, pushed in before `load()`) gates disk use: when false, `load()` starts empty and wipes any on-disk history, `save()` is a no-op, `setPersist(false)` drops the on-disk index at runtime, and `destroy()` wipes the files instead of saving. `destroy()` flushes synchronously (or wipes) — `disable()` must call it.
- **`lib/clipboardPopup.js`** — all the `St` UI, built as a **view-stack inside one grabbed actor**: a list view (search + rows, with a pinned-only filter toggle in the header) and a detail view reused for item-detail / edit / QR / **open-with** (an `Gio.AppInfo.get_recommended_for_type` app picker) / **remove-confirm** (shown only when deleting a pinned item). The back button (not Esc) returns to the list, to avoid fighting the GrabHelper's Esc handling. Uses the Shell's `GrabHelper` for the modal grab; don't hand-roll grabs (risks locking the session). Keyboard: typing filters, ↑/↓ move, → opens detail, Enter selects, Delete removes (Shift+Delete while a search query is active), Esc closes. Rows show a type icon / color swatch (from `contentType.js`), a truncated text preview or an image thumbnail (`Gio.FileIcon`), a relative timestamp, and per-row buttons (open-link, more, pin). The popup paints its own surface and follows the system light/dark scheme via a `clippo-light`/`clippo-dark` class (set from `org.gnome.desktop.interface` `color-scheme`, pushed in by `extension.js` as `popup.darkTheme`), with the selected row tinted by the accent color (`-st-accent-color`, neutral fallback); icon-only buttons set `accessible_name` for screen readers.
- **`lib/indicator.js`** — optional panel button; clicking calls back into `extension.js` to open the popup anchored below the icon.
- **`lib/quickToggle.js`** — a Quick Settings `QuickToggle` (+ `SystemIndicator`) bound to `private-mode`, to pause/resume capture from the system menu.
- **`lib/cycleOsd.js`** — a transient on-screen preview (own `St` actor in `uiGroup`, light/dark via the same `clippo-dark`/`clippo-light` class) shown while cycling the clipboard with the `cycle-next`/`cycle-previous` shortcuts; auto-hides ~1.5s after the last keypress. Deliberately not a libnotify notification.
- **`lib/contentType.js`** — pure helpers (no platform deps): `detectSubtype()` (url/color/email/code), `colorValue()`, `actionUri()`, `openWithType()` (the scheme-handler content type used to enumerate "open with" apps for url/email).
- **`lib/qrcodegen.js`** — vendored QR encoder (kazuhikoarase/qrcode-generator, MIT) for the QR view, drawn with `St.DrawingArea` + Cairo (the repaint handler must `$dispose()` the cairo context).

## Cross-cutting constraints

- **Super+V conflict:** GNOME binds `<Super>v` to `toggle-message-tray` (`['<Super>v','<Super>m']`). `_reconcileTrayConflict()` strips only `<Super>v` (leaving `<Super>m`) **while Clippo is actually bound to it**, re-checks on every `changed::toggle-clippo`, and hands it back when Clippo stops using it (and on `disable()`). Any change to keybinding setup must preserve restore-on-disable, or the user permanently loses Super+V for the message tray.
- **GNOME 48–50 API drift:** `St.BoxLayout` uses `orientation: Clutter.Orientation.VERTICAL` (not the deprecated `vertical`); `St.ScrollView` child-setting and the scroll `vadjustment` getter changed across these versions (`clipboardPopup.js` has the `_setScrollChild` / `_ensureRowVisible` shims). Image thumbnails use `Gio.FileIcon` on an `St.Icon` to sidestep the `St.ImageContent`/`Cogl.Context` differences. Keep new platform calls tolerant across the declared `shell-version` range.
- **Prefs resource path differs from extension.js (easy to get wrong):** `extension.js` and the `lib/` modules import Shell resources under `resource:///org/gnome/shell/...` (lowercase), but `prefs.js` runs in a *separate* process and must import the base class from `resource:///org/gnome/Shell/Extensions/js/extensions/prefs.js` (note the capital `Shell`/`Extensions` and the `/js/` segment). The lowercase `resource:///org/gnome/shell/extensions/prefs.js` does **not** exist in that process on GNOME 49/50 and fails with `ImportError: … prefs.js … does not exist` — even though `extension.js` (which loads inside gnome-shell) works fine. prefs.js is reloaded fresh each time it opens, so fixing it needs no logout.
- **Settings live in `schemas/`**: `max-items`, `toggle-clippo`, `show-indicator`, plus `private-mode`, `capture-primary`, `capture-images`, `trim-whitespace`, `detect-types`, `order-by-recent-use`, `excluded-apps`, `persist-history`, and the cycling shortcuts `cycle-next` / `cycle-previous`. All three shortcut keys (`toggle-clippo` included) are `as` and **default empty** — extensions.gnome.org forbids clipboard managers from shipping a default shortcut (a review MUST NOT). `extension.js` reacts at runtime (`changed::max-items`, `changed::show-indicator`, `changed::persist-history` → `store.setPersist()`, and `_applyCaptureSettings()` for the capture/popup-related keys), and registers `cycle-next`/`cycle-previous` via `Main.wm.addKeybinding` (removed on `disable()`). `prefs.js` (separate process, libadwaita) edits them, with a generalized custom key-capture (`_addShortcutRow` + `_captureShortcut(window, settings, key)`) for all three shortcuts (in an `Adw.Dialog`) and an add/remove list for `excluded-apps`. Separately, `extension.js` watches the external `org.gnome.desktop.interface` `color-scheme` key to follow the system light/dark theme.
- **Privacy:** capture can be paused (`private-mode`, also a Quick Settings toggle); content flagged by password managers (a `passwordManagerHint` MIME type) is skipped; per-app exclusion is supported (best-effort on Wayland — some clients expose no id). Images are **opt-in** (`capture-images`, off by default). The history file is 0600 but unencrypted, so non-flagged secrets can still land in history.
- **i18n:** user-facing strings are wrapped in `_()` (plurals via `ngettext`); `lib/clipboardPopup.js` / `lib/quickToggle.js` import `gettext`/`ngettext` from the extension resource module and `prefs.js` from the prefs resource module, both resolving the `clippo` domain set by `gettext-domain` in `metadata.json`. The base `Extension`/`ExtensionPreferences` classes auto-init translations. Keep new UI strings wrapped and add their `msgstr` to `po/*.po` (verify with `msgfmt --check`); never let a string bypass `_()` or it won't translate.
